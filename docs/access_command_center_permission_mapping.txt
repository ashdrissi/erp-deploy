ACCESS COMMAND CENTER PERMISSION MAPPING
========================================

Purpose
-------
This file is the operator-facing contract for Access Command Center. A checked
business permission must produce all access needed to use that feature, without
requiring hidden Role Permission Manager changes.

Role creation baseline
----------------------
Every Orderlift-managed custom role receives this technical Desk baseline. It
does not grant access to a business document, business menu, Page, or Report.

Address: read, report, print, email
Communication: read, report, print, email
Contact: read, report, print, email
Country: read, report, print, email
Currency: select
Email Template: read, report, print, email
Event: read, write, create, report, print, email
File: read, write, create, delete
Gender: read, report, print, email
Language: read, report, print, email
Notification Log: read, report, print, email
Payment Term: select
Payment Terms Template: read, report, print, email
Salutation: read, report, print, email
Tag: read, write, create
Tag Link: read, write, create
ToDo: select, read, write, create, delete
UOM: read, report, print, email

Business action mapping
-----------------------
Use in Fields: select
View: read, report, print
Create / Edit: read, write, create, report, print
Approve / Cancel: read, write, submit, cancel, amend
Delete: read, delete
Import: read, create, import
Export: read, export

Import tool dependency
----------------------
Import is a single Business Permissions action. In addition to the target
DocType mapping above, the compiler grants the minimum native tool access to
roles with at least one effective Import target:

Data Import: read, write, create
Data Import Log: read

These supporting DocTypes are runtime dependencies, not separate business
controls. They are hidden from the technical permission matrix and are
removed when the role has no remaining Import target.

General behavior for every row
------------------------------
1. Enabling an action also shows the corresponding Main Dashboard menu item.
2. A Page action adds the native Page role and all listed backing access.
3. A Report action adds the native Report role and reference DocType access.
4. A DocType row applies the action mapping to permlevel 0.
5. Child tables are included through their parent and are not exposed as
   misleading standalone business grants.
6. Curated reference dependencies receive only read or select access.
7. Runtime server capabilities listed below are included in the same action.
8. Disabling the final action removes the menu role, native target role, and
   grants owned by that feature while preserving grants required by other rows.
9. All changes clear DocType, role, user, menu, and boot caches as applicable.

There is intentionally no separate Menu Access tab. Orderlift Menu Access Rule
records remain compiled backend storage and a server-side safety check. They are
not an independent administrator control that can disagree with this matrix.

Role-level capabilities
-----------------------
Capabilities remain explicit role-level privileges except where a business row
lists one as part of its feature contract.

Privileged Pricing: broad pricing, cost, margin, and benchmark visibility.
Pricing Override: quotation and pricing-sheet price/discount override.
Manage Saved Other Charges: maintain reusable Other Charge records.
Purchasing Access: supplier costs, buying price lists, and purchasing workflows.
All ToDos Access: access ToDos beyond the user's own work.
Stock Rate Management: approve missing/provisional stock rates.
Commission Assignment Management: assign commission beneficiaries.
Commission Payout Management: approve and mark commission payouts.
Opportunity Pipeline Assignment: assign/unassign Opportunity cards only.
Project Pipeline Assignment: assign/unassign Project cards only.
Sales Order Pipeline Assignment: assign/unassign Sales Order cards only.
Manage Purchase Agent Rules: maintain company-scoped purchase-agent allowances.

Acceptance rule
---------------
A role is delivery-ready only when a disposable user with only that role can:
log in, load Desk without permission errors, see exactly the selected menus,
open selected features, perform selected actions, receive/read notifications,
and lose the access immediately after the corresponding toggle is disabled.
